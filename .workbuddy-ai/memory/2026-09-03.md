# 2026-09-03 — QC Review page updates

## What changed
User reported 4 issues on the GUI QC Review page. All four are fixed.

### 1. Show Pending QC by default
- `qc_gui()` in `app.py`: when `qc_status` query param is missing/empty/invalid, we default to `"pending"` so the page shows only pending records out of the box. A new `qc_status_default` flag is passed to the template so a small "(default)" hint appears next to the dropdown label until the user overrides it.
- `templates/qc_gui.html`: dropdown re-ordered with `Pending` as the default option and an explicit `All` option (no more URL-only "blank value").

### 2. Fix QC Done filter (30 records on 02-09-2026 not appearing)
- Root cause: when status=`done`, the date range filter was still applied to `inserted_date` (record-creation date), not to `qc_approved_date` (the date the QC was actually completed).
- Fix: in `qc_gui()` we now pick the date column based on the status:
  - `qc_status == "done"` → date range filters `qc_approved_date`
  - `pending` / `all` → still uses `inserted_date` (existing semantics for those filters).
- Same fix applied to `/qc-gui-export` so the exported CSV matches what the user sees on screen.

### 3. Automatic Daily QC Allocation
- New constant `AUTO_QC_DAILY_LIMIT = 70` next to `QC_TABLE`.
- New helper `_auto_allot_qc_for_user(user_name, daily_limit)` runs idempotently on every `/qc-gui` page load:
  - Counts `input_user = X AND qc_status IS NULL AND qc_assigned_date = today` (already_today).
  - Counts the remaining pending pool (`qc_status IS NULL` but not yet slotted into today).
  - If `already_today < daily_limit`, pick the oldest `need = min(limit - already_today, pending_pool)` records (FIFO, by `id ASC`) and bulk-update their `qc_assigned_date = today`.
- New filter-header chip "Today's Auto-Allot: x/70 (pending: y • +n new today)" makes this state visible to the user.

### 4. Highlight Pending and QC Done rows
- Row coloring added in `templates/qc_gui.html` (light theme + matching dark theme equivalents):
  - `qc-row-pending` → soft amber `#fff7d6`
  - `qc-row-done-true` → soft green `#e8f8f0` (matches existing badges)
  - `qc-row-done-false` → soft red `#fdecea` (matches existing badges)
- A small legend swatch set sits in the filter header so the meaning is obvious.

## Files touched
- `app.py` — added constant + helper, refactored `qc_gui()` defaults and date filter, mirrored in `qc_gui_export()`.
- `templates/qc_gui.html` — CSS for row highlight + legend + auto-allot chip, dropdown reorder, export form `qc_status` hidden field, row class on `<tr>`.

### 5. Role-based visibility refinement (follow-up)
- QC Status filter: **Admin** gets full dropdown Pending / QC Done / QC Rejected / All. **User** gets a limited Pending / QC Done dropdown only (Rejected & All are admin-only).
- Added new `qc_status = "rejected"` value → backend filters `qc_status == False` (both `qc_gui()` and `qc_gui_export()`).
- Server-side enforcement: non-admins requesting `rejected`/`all` are forced back to `pending` (defense in depth against crafted URLs).
- Auto-Allotment chip in the filter header is now `{% if is_admin %}` only.
- Legend's "QC Rejected" swatch hidden for non-admins.
- User-end table carries class `user-view` (when not admin); CSS neutralizes the rejected-row red tint so users never see a highlighted rejected row. Pending (amber) + QC Done (green) still highlight on the user end; Rejected never does.

### 6. Per-user data isolation on QC page (Rozma saw 303 instead of 89)
- The page query previously had NO user filter — non-admins saw every record across all users (Rozma was seeing 303 QC-Done rows instead of her own 89).
- Fix in `qc_gui()`: when `not is_super_or_admin`, scope the main query by:
  - `qc_status == "done"` → `query.eq("approved_by", current_user_name)` (records I personally completed)
  - `qc_status == "pending"` → `query.eq("input_user", current_user_name)` (records allotted to me)
- Same isolation applied to `/qc-gui-export` so the CSV only includes the current user's data for non-admins.
- Admin behaviour is unchanged (they keep the global view of every record).
